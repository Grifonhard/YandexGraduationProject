## AUTH
На стороне сервера хранятся хэшированный пароль. Соль хранится на стороне клиента.

### Создание нового пользователя
Когда появляется новый пользователь - создаётся временный одноразовый пароль на сервере. Пароль предоставляется пользователю. Пользователь выбирает в клиенте залогиниться или зарегистрироваться. При регистрации он вводит пароль и логируется. Логин с временным паролем срабатывает 1 раз. Ему приходит токен, с котором он аутентифицируется в дальнейшем. Пользователь может указать новое имя и обязательно указывает новый пароль. Первым меняется пароль. На сервере одноразовый пароль хранится в не хешированном виде. При создании нового пароля на клиенте создаётся тут же соль, пароль хэшируется и отправляется на сервер для записи в бд. Если имя пользователя тоже надо менять, то происходит автологин и замена токена. Вторым меняется имя пользователя. После этих операций происходит разлогин, пользователь должен залогиниться заново.

### Логин
Пользователь указывает имя пользователя, пароль на клиенте. Клиент хэширует пароль солью из своей бд. Отправляет запрос на сервер. Сервер проверяет пароль и возвращает токен. Дальнейшие действия просиходят с помощью аутентификации токеном.

#### Логин с нового экземпляра клиента
Клиент проверяет есть ли в бд соль. Если соли нет, то это первый запуск на этом устройстве. Клиент собирает информацию об устройстве: ОС, серийный номер материнской платы если есть, локальное время, локацию, ip, мак адрес. Отправляет запрос на сервер. На сервере этот запрос запускает горутину и запрос подвисает. В горутине мы ждём сигнал аутентификации из другого клиента. Как только получаем атентификацию из другого действующего клиента - отправляем запрос этому клиенту на разрешение транслировать соль из из действующего клиента. Если разрешение получено, то скачиваем соль на сервер и тут же в горутине возвращаем соль недействительному клиенту. После этого клиент становится действующим.

### Аутентификация
При аутентификации от клиента отправляем в заголовке данные о мак адресе, а на сервере вытаскиваем ip адрес. Всё это сверяем с данными в токене. Токены уникальны для каждого клиента и для каждого пользователя. Хранятся в отдельной табличке.
